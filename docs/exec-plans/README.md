# 执行计划分层说明

这层不是为了多造文档，而是把 **正在推进**、**已经完成**、**仍属技术债/待补缺口** 分开，避免所有方案长期混堆在 `docs/plans/` 里。

## 目录约定
- `active/`：当前仍在推进、仍会继续回写的执行稿
- `completed/`：已经收口完成、只留归档和复盘价值的执行稿
- `tech-debt-tracker.md`：暂不单独起目录的技术债/治理缺口跟踪板

## 使用边界
1. `docs/plans/` 继续保留历史方案与专题方案，不强行一次性迁仓。
2. 真正进入执行态、需要持续回写的主线稿，后续优先落到 `active/`。
3. 一旦完成验收、证据和 closeout，应从 `active/` 下沉到 `completed/`。
4. `current-progress-board.md` 仍是主板；这里是计划分层，不替代主板。
5. 不允许把“只有想法、还没进入执行”的草稿伪装成 active 执行稿。

## 与现有体系关系
- 主板：看当前到哪、卡在哪、下一步是什么
- active plans：看当前执行稿与验收边界
- completed plans：看已收口方案与可复用经验
- closeout：看正式收口结论
- runbook / SOP：看具体怎么操作
